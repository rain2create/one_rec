# One-Rec 推理后处理详解

## 一、去掉无效码本组合

### 1.1 为什么会有无效组合？

码本虽然是3层，但并不是所有 `[layer1, layer2, layer3]` 的组合都对应真实存在的视频。

```
假设码本大小：
- 第1层：1500 个码字
- 第2层：1500 个码字  
- 第3层：1500 个码字

理论组合数：1500 × 1500 × 1500 = 33.75 亿种
实际视频数：可能只有 1000 万个

有效组合占比：1000万 / 33.75亿 ≈ 0.3%
```

**大部分组合是无效的！**

### 1.2 无效组合的成因

```
训练阶段：
- 模型学习的是"从视频ID → 3层码本"的映射
- 这个映射是 RQ-VAE 或 K-means 生成的

推理阶段：
- 模型生成 [tok1, tok2, tok3]
- 需要去码本查找表中反查对应的视频URL
- 如果 [tok1, tok2, tok3] 在查找表中不存在 → 无效组合
```

### 1.3 sample_mask 的作用

```python
# 在 parser/tokenizer.py 中的解码逻辑
def batch_decode_processed(self, output_ids, device):
    """
    output_ids: [B, group_num, 3] - 生成的3层码本ID
    
    返回:
    - urls: 反查得到的URL列表
    - sample_mask: [B, group_num] - 标记哪些组合是有效的
    """
    urls = []
    sample_mask = []
    
    for batch_idx in range(B):
        for beam_idx in range(group_num):
            code = output_ids[batch_idx, beam_idx].tolist()  # [tok1, tok2, tok3]
            
            # 在码本查找表中查询
            url = self.codebook_lookup.get(tuple(code), None)
            
            if url is not None:
                urls.append(url)
                sample_mask.append(True)   # ✅ 有效组合
            else:
                urls.append("INVALID")     # ❌ 无效组合
                sample_mask.append(False)
    
    return urls, torch.tensor(sample_mask)

# 使用
valid_urls = urls[sample_mask]  # 只保留有效的URL
```

### 1.4 实际例子

```python
# 假设生成了5个候选
generated_codes = [
    [100, 200, 50],    # ✅ 有效 → URL: "https://video1.com"
    [150, 300, 80],    # ❌ 无效（查无此组合）
    [120, 220, 60],    # ✅ 有效 → URL: "https://video2.com"
    [999, 888, 777],   # ❌ 无效（查无此组合）
    [110, 210, 55],    # ✅ 有效 → URL: "https://video3.com"
]

sample_mask = [True, False, True, False, True]

# 过滤后
valid_urls = ["https://video1.com", "https://video2.com", "https://video3.com"]
# 从5个候选变成3个有效候选
```

### 1.5 为什么需要过滤？

| 问题 | 说明 |
|------|------|
| **不能推荐不存在的视频** | 无效组合无法映射到真实URL |
| **影响评估指标** | 如果不过滤，hitrate 会被拉低 |
| **用户体验** | 推荐了一个打不开的链接 |

## 二、多样性重排

### 2.1 为什么需要多样性？

即使都是有效URL，也可能出现以下问题：

```
问题1: 重复推荐
  候选1: "猫吃饭视频A"
  候选2: "猫吃饭视频B"（和A几乎一样）
  候选3: "猫吃饭视频C"（和A几乎一样）
  → 用户看到的都是雷同内容！

问题2: 主题单一
  候选1: "篮球精彩进球"
  候选2: "篮球教学"
  候选3: "篮球比赛"
  → 用户可能还想看足球、乒乓球！

问题3: 同一作者
  候选1: "UP主X的搞笑视频1"
  候选2: "UP主X的搞笑视频2"
  候选3: "UP主X的搞笑视频3"
  → 全是同一个人的！
```

### 2.2 diversity_rerank 的核心思想

```python
def diversity_rerank(urls, top_k=5):
    """
    从候选URL中选择 top_k 个，保证多样性
    
    策略1: 去重（基于视频特征相似度）
    策略2: 作者打散（避免同一作者连续出现）
    策略3: 标签打散（覆盖不同主题）
    策略4: MMR（最大边缘相关）
    """
    
    selected = []
    candidates = urls.copy()
    
    while len(selected) < top_k and candidates:
        if not selected:
            # 第一个选分数最高的
            best = max(candidates, key=lambda x: x['score'])
        else:
            # 后续选择：既高分又与已选不相似的
            best = None
            best_score = -float('inf')
            
            for candidate in candidates:
                # MMR 分数 = λ * relevance - (1-λ) * max_similarity(selected)
                relevance = candidate['score']  # 相关性（模型分数）
                
                # 计算与已选的最大相似度
                max_sim = max([similarity(candidate, s) for s in selected])
                
                # MMR 公式
                mmr_score = 0.7 * relevance - 0.3 * max_sim
                
                if mmr_score > best_score:
                    best_score = mmr_score
                    best = candidate
        
        selected.append(best)
        candidates.remove(best)
    
    return selected
```

### 2.3 多样性度量方法

#### 方法1: 基于视频Tag的相似度

```python
def similarity_by_tag(video1, video2):
    """
    基于视频标签的Jaccard相似度
    """
    tags1 = set(video1['tags'])  # {'猫', '萌宠', '搞笑'}
    tags2 = set(video2['tags'])  # {'猫', '萌宠', '吃饭'}
    
    intersection = len(tags1 & tags2)  # 2 ('猫', '萌宠')
    union = len(tags1 | tags2)         # 4 ('猫', '萌宠', '搞笑', '吃饭')
    
    return intersection / union  # 2/4 = 0.5
```

#### 方法2: 基于Embedding的余弦相似度

```python
def similarity_by_embedding(video1, video2):
    """
    基于视频向量表示的余弦相似度
    """
    emb1 = video1['embedding']  # [768] 视频标题+封面图的向量
    emb2 = video2['embedding']  # [768]
    
    return torch.cosine_similarity(emb1, emb2, dim=0)
```

#### 方法3: 基于作者的去重

```python
def penalize_same_author(candidate, selected):
    """
    如果候选和已选是同一作者，降低分数
    """
    penalty = 0
    for s in selected:
        if candidate['author_id'] == s['author_id']:
            penalty += 0.3  # 每次重复扣0.3分
    
    return candidate['score'] - penalty
```

### 2.4 MMR (Maximal Marginal Relevance) 算法

```
MMR 分数 = λ × 相关性 - (1-λ) × 最大相似度

参数:
- λ = 0.7 (相关性权重)
- 1-λ = 0.3 (多样性权重)

例子：
已选: [视频A(猫)]
候选: 
  - 视频B(猫, score=0.9, sim(A,B)=0.9) → MMR = 0.7×0.9 - 0.3×0.9 = 0.36
  - 视频C(狗, score=0.8, sim(A,C)=0.1) → MMR = 0.7×0.8 - 0.3×0.1 = 0.53 ← 胜出！
  
虽然视频B分数更高，但和A太像了，所以选C！
```

### 2.5 完整示例

```python
# 输入：6个候选（已过滤无效）
candidates = [
    {'url': 'video1', 'score': 0.95, 'tags': {'猫','萌宠'}, 'author': 'A'},
    {'url': 'video2', 'score': 0.92, 'tags': {'猫','萌宠'}, 'author': 'A'},  # 和1太像
    {'url': 'video3', 'score': 0.88, 'tags': {'狗','萌宠'}, 'author': 'B'},
    {'url': 'video4', 'score': 0.85, 'tags': {'篮球','体育'}, 'author': 'C'},
    {'url': 'video5', 'score': 0.82, 'tags': {'猫','搞笑'}, 'author': 'D'},
    {'url': 'video6', 'score': 0.80, 'tags': {'美食',' cooking'}, 'author': 'E'},
]

# Greedy选择（top3分数）
greedy_result = [video1, video2, video3]
# 问题：video1和video2几乎一样（都是A作者的猫视频）

# 多样性重排（MMR, λ=0.7）
diversity_result = []

# 第1轮：选分数最高的
select video1 (score=0.95)
diversity_result = [video1]

# 第2轮：计算MMR
video2: MMR = 0.7×0.92 - 0.3×0.9 = 0.37   # 和video1太像，扣分多
video3: MMR = 0.7×0.88 - 0.3×0.3 = 0.53   # 和video1不同（狗vs猫），胜出！
video4: MMR = 0.7×0.85 - 0.3×0.1 = 0.57   # 体育和萌宠差异大，胜出！
... 选 video4

diversity_result = [video1, video4]

# 第3轮：计算MMR（与已选1和4的相似度）
video2: MMR = 0.7×0.92 - 0.3×max(0.9,0.1) = 0.37
video3: MMR = 0.7×0.88 - 0.3×max(0.3,0.2) = 0.49   ← 胜出！
video5: MMR = 0.7×0.82 - 0.3×max(0.7,0.1) = 0.36   # 和video1都是猫
video6: MMR = 0.7×0.80 - 0.3×max(0.1,0.1) = 0.53

... 选 video3
diversity_result = [video1(猫), video4(篮球), video3(狗)]

# 最终结果：猫、篮球、狗 —— 三个不同主题！
```

## 三、完整流程图

```
模型生成（Beam Search, group_num=5）
    ↓
[code1, code2, code3, code4, code5]
    ↓
码本反查 + sample_mask
    ↓
[url1(valid), INVALID, url3(valid), INVALID, url5(valid)]
    ↓
过滤无效: urls[sample_mask]
    ↓
[url1, url3, url5]  （只剩3个）
    ↓
多样性重排 diversity_rerank
    ↓
[url3(狗), url1(猫), url5(美食)]  （按MMR排序）
    ↓
取TopN返回给用户
```
