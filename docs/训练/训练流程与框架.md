## 2. 阶段一：预训练详解（train_pt.py）

### 2.1 Loss 组成

```python
# decoder.forward() 中的 loss 计算
total_loss = ct_loss + rl_loss + aux_loss
```

| Loss 类型 | 计算位置 | 作用 | 输入数据 |
|-----------|----------|------|----------|
| **NTP Loss (ct_loss)** | `decoder.py:385-393` | 标准Next Token Prediction | 曝光样本的目标视频URL |
| **RL Loss** | `decoder.py:401-408` | 基于advantage的Policy Gradient | 曝光样本 + advantage权重 |
| **Aux Loss** | `decoder.py:396-399` | MoE专家负载均衡 | - |

### 2.2 RL Loss 详细逻辑

```python
def rl_loss(self, features, pi_new):
    # pi_new: 模型对目标视频的预测概率
    # features['advantages']: 预计算的奖励权重
    
    # 构建安全策略
    pi_safe = torch.where(features['advantages'] > 0.0, pi_new, 1.0 - pi_new)
    
    # 计算比率
    ratio = pi_new / pi_safe.detach()
    
    # Policy Gradient（只使用正负样本，中性样本mask掉）
    mask = (features['advantages'] != 0.0)
    loss = -(ratio * features['advantages'])
    loss = (loss * mask).sum() / (mask.sum().clamp_min(1))
    
    return loss
```

**关键点**：
- 不是**生成式**RL（不生成新候选）
- 是**重要性加权**（对曝光样本按advantage加权）
- 正样本：最大化预测概率
- 负样本：最小化预测概率

### 2.3 与标准RL的区别

| 对比项 | 标准RL (PPO/GRPO) | 预训练RL Loss |
|--------|-------------------|---------------|
| 候选来源 | 模型生成 (Generate) | 曝光日志 (Exposure) |
| Reward计算 | 外部模型打分 | 预计算advantage |
| 优化目标 | 提升生成质量 | 拟合曝光分布 |
| 训练效率 | 慢（需采样生成） | 快（直接使用曝光数据） |

## 3. 阶段二：RL微调详解（train_grpo_neg_sample.py）

### 3.1 完整流程

```
输入：用户行为特征
    ↓
1. Beam Search生成 (group_num=G)
   对每个用户生成G个候选视频
   [url_1, url_2, ..., url_G]
    ↓
2. Reward模型打分
   通过gRPC调用TF Serving
   多目标预测：[like, follow, zmtlink, ...]
   reward = Σ(weight_i × score_i)
    ↓
3. 计算优势 (GRPO)
   advantages = (rewards - rewards.mean()) / rewards.std()
    ↓
4. 策略更新
   loss = -E[advantage × log_prob]
```

### 3.2 GRPO vs GBPO

| 算法 | 全称 | 特点 | 使用场景 |
|------|------|------|----------|
| **GRPO** | Group Relative Policy Optimization | 组内标准化优势，无需value网络 | 主RL训练 |
| **GBPO** | Gradient-Based Policy Optimization | 基于梯度的策略优化，带clip | 稳定训练 |

```python
# GRPO Loss（核心实现）
def compute_sample_loss(old_log_prob, new_log_prob, advantage, clip_epsilon=0.1):
    ratio = torch.exp(new_log_prob - old_log_prob)
    surr1 = ratio * advantage
    surr2 = torch.clamp(ratio, 1-clip_epsilon, 1+clip_epsilon) * advantage
    loss = -torch.min(surr1, surr2).mean()
    return loss
```

## 4. 训练框架使用情况

### 4.1 框架清单

| 框架/库 | 使用情况 | 具体用途 |
|---------|----------|----------|
| **PyTorch** | ✅ 核心框架 | 模型定义、训练循环、反向传播 |
| **HuggingFace Transformers** | ⚠️ 部分使用 | 仅使用 `HfArgumentParser` 解析参数 |
| **OpenRLHF** | ❌ 未使用 | - |
| **VeRL** | ❌ 未使用 | - |
| **TRL** | ❌ 未使用 | - |
| **Ray** | ❌ 未使用 | - |
| **vLLM** | ❌ 未使用 | - |
| **DeepSpeed** | ❌ 未使用 | - |

### 4.2 自研组件

| 组件 | 实现位置 | 功能 |
|------|----------|------|
| RL Loss (预训练) | `model/decoder.py:316-354` | 基于曝光样本的Policy Gradient |
| GRPO/GBPO | `train_grpo_neg_sample.py:50-84` | 组相对策略优化 |
| Advantage计算 | `reward/reward_algorithm.py` | 标准化、解码奖励等 |
| Reward模型 | `reward/reward_scorer_online.py` | gRPC调用TF Serving |
| 训练循环 | `train_pt.py`, `train_grpo_neg_sample.py` | 自定义训练逻辑 |

### 4.3 结论

**所有RL算法均为自研实现**，没有使用任何开源RL框架（OpenRLHF、VeRL、TRL等）。

原因可能是：
1. 推荐系统的RL逻辑与LLM不同（不需要vLLM加速生成）
2. 需要高度定制化（与内部Reward服务集成）
3. 模型规模适中（2.3亿参数），不需要DeepSpeed等大规模训练框架
