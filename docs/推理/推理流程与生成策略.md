# One-Rec 模型推理详解

## 一、推理整体流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         One-Rec 推理流程                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  输入：用户历史行为特征（131维CSV）                                          │
│      ↓                                                                      │
│  ┌──────────────┐                                                          │
│  │ SparseModel  │  → 将用户ID、视频ID等离散特征映射为Embedding              │
│  └──────────────┘                                                          │
│      ↓ [B, 4] + [B, 30, 7] + [B, 30, 7] + [B, 30, 4]                       │
│  ┌──────────────┐                                                          │
│  │   Encoder    │  → Transformer编码，输出上下文表示                        │

│  ┌──────────────┐                                                          │

```

## 二、生成策略对比

One-Rec 支持三种生成策略，核心区别在于**如何从概率分布中选择下一个token**。

### 2.1 Greedy（贪心）- 基线方法

```python
def _sample_from_logits(self, logits, strategy="greedy"):
    next_token = torch.argmax(logits, dim=-1)
```

**原理**：
- 每一步都选择概率最高的token
- **确定性**：同样的输入永远输出同样的结果

**缺点**：
- 缺乏多样性，容易生成重复内容
- 无法探索其他可能的优质候选

```
例子：
logits = [0.1, 0.2, 0.5, 0.15, 0.05]
              ↑
          选择0.5对应的token
```

---

### 2.2 TopK - 限制候选池

```python
elif strategy == "topk":
    topk_logits, topk_indices = torch.topk(logits, top_k, dim=-1)  # 只保留topk
    probs = F.softmax(topk_logits, dim=-1)  # 重新归一化
    next_token = torch.multinomial(probs, 1).squeeze(-1)  # ⚠️ 按概率随机采样！
    next_token = topk_indices.gather(-1, next_token.unsqueeze(-1)).squeeze(-1)
```

**原理**：
1. 从全部vocab（1502个）中选出概率最高的 **K** 个
2. 在这K个中按概率重新归一化（softmax）
3. 从归一化后的分布中**按概率随机采样**（不是取最大！）

**⚠️ 注意**：`torch.multinomial` 是**随机采样**，不是 `argmax`！

**参数**：
- `top_k=50`：从1502个中选50个，再采样
- `top_k=10`：更保守，只考虑前10个

```
例子（K=3）：
原始logits: [0.1, 0.2, 0.5, 0.15, 0.05]  (vocab_size=5)
                ↓
Top3选择:    [0.5, 0.2, 0.15]  (对应索引2,1,3)
                ↓
重新归一化:  [0.588, 0.235, 0.176]  (softmax后)
                ↓
multinomial采样:
    - 58.8% 概率选索引2 (原概率0.5)
    - 23.5% 概率选索引1 (原概率0.2)  
    - 17.6% 概率选索引3 (原概率0.15)
```

### 关键：multinomial 是随机采样，不是 argmax！

**Python代码验证**:

```python
import torch

# 假设 Top3 后的归一化概率
probs = torch.tensor([0.588, 0.235, 0.176])

print("=== argmax (确定性) ===")
for i in range(5):
    result = torch.argmax(probs)
    print(f"第{i+1}次: 永远选索引{result.item()}")
# 输出: 0, 0, 0, 0, 0  (永远一样！)

print("\n=== multinomial (随机性) ===")
torch.manual_seed(42)
for i in range(5):
    result = torch.multinomial(probs, 1)
    print(f"第{i+1}次: 选索引{result.item()}")
# 输出: 0, 2, 0, 1, 0  (居然选到了概率最小的索引2！)
```

**对比**:

| 方法 | 代码 | 结果 | 特点 |
|------|------|------|------|
| **argmax** | `torch.argmax([0.588, 0.235, 0.176])` | **永远选第1个** (0.588) | 确定性，无随机性 |
| **multinomial** | `torch.multinomial([0.588, 0.235, 0.176], 1)` | **58.8%选第1个，23.5%选第2个** | 随机性，按概率采样 |

**实际效果**:

假设 Top3 = [A, B, C]，概率 [0.6, 0.3, 0.1]

- **第1次采样**：可能选 A（概率60%），也可能选 B（概率30%）
- **第2次采样**：还是可能选 A，也可能选 C（概率10%）
- **第100次采样**：大约 60次选A，30次选B，10次选C

这就是**多样性**的来源：不是永远选最好的，而是给好的更高的概率，但偶尔也尝试其他的。

**优点**：
- 比Greedy有更多多样性（不会每次都生成一样的结果）
- 比完全随机更可控（只在高质量的TopK中选择）

**缺点**：
- K值不好确定（分布平坦时K=50可能包含很多低概率token）
- 分布尖锐时K=50可能浪费（前几个就占了99%概率）

### 2.3 TopP (Nucleus Sampling) - 动态候选池

```python
elif strategy == "topp":
    sorted_logits, sorted_indices = torch.sort(logits, descending=True, dim=-1)
    probs = F.softmax(sorted_logits, dim=-1)
    cumulative_probs = torch.cumsum(probs, dim=-1)  # 累积概率
    
    # 创建mask：累积概率超过p的部分置0
    mask = cumulative_probs > top_p
    mask[..., 1:] = mask[..., :-1].clone()
    mask[..., 0] = False
    
    filtered_probs = probs.masked_fill(mask, 0.0)
    next_token = torch.multinomial(filtered_probs, 1).squeeze(-1)
    next_token = sorted_indices.gather(-1, next_token.unsqueeze(-1)).squeeze(-1)
```

**原理**：
1. 将token按概率从大到小排序
2. 计算累积概率，直到超过阈值 **P**
3. 只在这个**最小候选集**中采样

**参数**：
- `top_p=0.9`：选择概率累积到90%的最小token集合
- `top_p=0.5`：更严格，只选前50%概率的token

```
例子（P=0.9）：
排序后:      [0.5, 0.2, 0.15, 0.1, 0.05]
                ↓
累积概率:    [0.5, 0.7, 0.85, 0.95, 1.0]
                ↓
选前4个(>0.9): [0.5, 0.2, 0.15, 0.1]  (累积0.95≥0.9)
                ↓
归一化采样:    [0.526, 0.211, 0.158, 0.105]
```

**优点**：
- **自适应**：分布平坦时选得多，尖锐时选得少
- 比TopK更智能

**实验结果**（来自docs/experiments.md）：

| topp | like_hits | pos_hitrate | recall_urls |
|------|-----------|-------------|-------------|
| 0.9 | 2,714 | 0.0246 | 39,683 |
| **0.5** | **3,494** | **0.0415** | 50,428 |
| 0.1 | 1,531 | 0.0181 | 17,691 |

**结论**：TopP=0.5 是最佳平衡点

### 2.4 Beam Search - 全局最优

#### 什么是"分数"？

**分数 = 累计 log 概率**（对数概率相加）

```python
# 为什么用 log 概率？
# 概率相乘会变成小数溢出，log 概率相加更安全
seq_prob = p1 * p2 * p3        # 容易下溢 (0.001 * 0.002 = 0.000002)
log_prob = log(p1) + log(p2) + log(p3)  # 更安全 (-6.9 + -6.2 = -13.1)
```

#### Beam Search 核心流程

```python
def bs_rl_generate(self, encoder_output, encoder_mask, group_num=5):
    # 初始化：group_num 个候选，都从 BOS 开始
    input_ids = torch.full((B*group_num, 1), BOS)  # [B*5, 1]
    scores = torch.zeros(B*group_num)              # [B*5] 初始分数为0
    
    for step in range(3):  # 3层码本
        # Step 1: 每个当前候选扩展 group_num 个子候选
        # 当前有 5 个候选，每个生成 5 个子候选 → 共 25 个候选
        log_probs = F.log_softmax(logits, dim=-1)  # [B*5, 1502]
        topk_log_probs, topk_tokens = torch.topk(log_probs, group_num, dim=-1)
        # topk_log_probs: [B*5, 5] - 每个候选的 top5 log概率
        
        # Step 2: 计算新分数 = 父分数 + 子log概率
        # scores: [B*5, 1, 1] + topk_log_probs: [B*5, 5] → [B, 5, 5]
        new_scores = current_scores.unsqueeze(2) + topk_log_probs
        
        # Step 3: 从 25 个候选中选择分数最高的 5 个！
        # ⚠️ 关键：不是每层取最大，而是全局保留最优的5个
        top_scores, top_indices = torch.topk(new_scores.view(B, -1), group_num, dim=1)
        
        # Step 4: 只保留选中的5个，其他20个丢弃
        input_ids = input_ids[global_old_beam_indices]
        scores = top_scores.view(-1)
```

#### 具体例子（group_num=2，3层码本）

假设我们要生成3层码本 `[layer1, layer2, layer3]`，每层有4个可能token [A, B, C, D]。

**Step 0: 初始化**
```
候选列表: [BOS]
分数:     [0.0]
```

**Step 1: 第1层（从1个扩展出2个子候选）**
```
BOS 可以生成: A(log_p=-0.5), B(log_p=-0.8), C(log_p=-1.2), D(log_p=-1.5)

全部候选:
  BOS→A: 分数 = 0 + (-0.5) = -0.5
  BOS→B: 分数 = 0 + (-0.8) = -0.8
  BOS→C: 分数 = 0 + (-1.2) = -1.2
  BOS→D: 分数 = 0 + (-1.5) = -1.5

按分数排序: A(-0.5) > B(-0.8) > C(-1.2) > D(-1.5)

⚠️ 保留 top2: [A(-0.5), B(-0.8)]
   丢弃: [C, D]  (虽然C和D也是可能的，但分数低，暂时放弃)
```

**Step 2: 第2层（2个候选各扩展2个 → 4个候选，再选top2）**
```
从 A(-0.5) 扩展:
  A→A: 分数 = -0.5 + (-0.4) = -0.9   (AA)
  A→B: 分数 = -0.5 + (-0.7) = -1.2   (AB)
  
从 B(-0.8) 扩展:
  B→A: 分数 = -0.8 + (-0.3) = -1.1   (BA)
  B→B: 分数 = -0.8 + (-0.9) = -1.7   (BB)

全部4个候选:
  AA: -0.9  ← 当前最好！
  AB: -1.2
  BA: -1.1
  BB: -1.7

⚠️ 按分数排序，保留 top2: [AA(-0.9), BA(-1.1)]
   注意：BA(-1.1) 比 AB(-1.2) 好，所以选BA而不是AB！
   
   关键洞察：虽然 A 在第1层是最好的，但 A→B 组合不好。
   而 B 在第1层是第2名，但 B→A 组合反而更好！
   这就是 Beam Search 的优势：有机会纠正早期选择。
```

**Step 3: 第3层（2个候选各扩展2个 → 4个候选，再选top2）**
```
从 AA(-0.9) 扩展:
  AA→A: 分数 = -0.9 + (-0.4) = -1.3  (AAA)
  AA→B: 分数 = -0.9 + (-0.6) = -1.5  (AAB)

从 BA(-1.1) 扩展:
  BA→A: 分数 = -1.1 + (-0.3) = -1.4  (BAA)
  BA→B: 分数 = -1.1 + (-0.8) = -1.9  (BAB)

全部4个候选:
  AAA: -1.3  ← 最终冠军！
  AAB: -1.5
  BAA: -1.4  ← 亚军！
  BAB: -1.9

⚠️ 最终输出 top2: [AAA(-1.3), BAA(-1.4)]
```

**对比 Greedy 的结果**:
```
Greedy 路径:
  Step1: 选 A(-0.5)  ← 当前最好
  Step2: 从A选 AA(-0.9)  ← 当前最好
  Step3: 从AA选 AAA(-1.3)  ← 当前最好
  结果: AAA

Beam Search 路径:
  Step1: 保留 [A, B]  ← 不急于决定
  Step2: 从4个候选中发现 BA 也不错
  Step3: 最终输出 [AAA, BAA]  ← 全局最优
  
  注意：虽然 AAA 都是最优，但 Beam Search 还发现 BAA 是次优选择，
       而 Greedy 永远只能找到一个答案。
```

#### 关键概念：为什么分数是累计的？

```python
# 分数 = log(p1) + log(p2) + log(p3)
# 对应概率 = exp(分数) = p1 * p2 * p3

AAA: 分数=-1.3 → 概率 = exp(-1.3) = 0.27
BAA: 分数=-1.4 → 概率 = exp(-1.4) = 0.25
AAB: 分数=-1.5 → 概率 = exp(-1.5) = 0.22

分数越高(-1.3 > -1.4 > -1.5)，概率越大！
```

#### Beam Search vs 其他策略

| 策略 | 第1层 | 第2层 | 第3层 | 特点 |
|------|-------|-------|-------|------|
| **Greedy** | 选A(-0.5) | 选AA(-0.9) | 选AAA(-1.3) | 只保留1个，局部最优 |
| **TopK** | 从[A,B,C,D]采样 | 从子候选采样 | 从子候选采样 | 随机，多样性高 |
| **Beam Search** | 保留[A,B] | 保留[AA,BA] | 保留[AAA,BAA] | 保留多个，全局最优 |

#### 回答你的问题

**Q: 分数是什么？**
> 分数是**累计 log 概率**，表示从 BOS 开始到当前token的联合概率的对数。
> 分数 = log(p1) + log(p2) + ... + log(pk)

**Q: 按分数排序然后取最大的那个？**
> **不是！** Beam Search 每一步保留 **group_num 个**（如5个），不是1个。
> - 第1步：从4个中保留 top2
> - 第2步：从4个中保留 top2  
> - 第3步：从4个中保留 top2
> 
> 最终输出的是**分数最高的 group_num 个序列**，按分数排序。

**Q: 和 Greedy 有什么区别？**
> - Greedy：每步只保留1个最好的，可能错过全局最优（如上面的 BA 路径）
> - Beam Search：每步保留 group_num 个，有机会发现"早期一般但后期很好"的路径

**实验结果**（来自docs/experiments.md）：

| 生成策略 | like_hits | pos_hitrate | recall_urls | 链接命中率 |
|----------|-----------|-------------|-------------|------------|
| **BeamSearch** | 5,450 | **0.0928** | 38,159 | **9.28%** |
| TopK=30 | 4,004 | 0.0472 | 52,088 | 4.72% |
| TopP=0.5 | 3,494 | 0.0415 | 50,428 | 4.15% |

**结论**：Beam Search 命中率最高（9.28%），但生成URL数最少（多样性低）

## 三、策略选择建议

### 3.1 根据业务需求选择

| 需求 | 推荐策略 | 参数 | 原因 |
|------|----------|------|------|
| **要指标**（点击率） | Beam Search | group_num=5 | 命中率高，精准推荐 |
| **要多样性** | TopK | k=30 | 生成更多不同URL |
| **要平衡** | TopP | p=0.5 | 自适应，综合最优 |
| **快速测试** | Greedy | - | 确定性，可复现 |

### 3.2 代码调用方式

```python
# 1. Beam Search（推荐用于生产）
model.generate(features, group_num=5)  # 内部调用 bs_rl_generate

# 2. TopK
model.rl_generate(features, group_num=5, top_k=30, strategy="topk")

# 3. TopP
model.rl_generate(features, group_num=5, top_p=0.5, strategy="topp")

# 4. Greedy（默认）
model.rl_generate(features, group_num=1, strategy="greedy")
```

## 四、推理性能

### 4.1 生成策略耗时对比

| 策略 | 计算量 | 相对速度 | 适用场景 |
|------|--------|----------|----------|
| Greedy | O(1) | 1x | 测试、基线 |
| TopK | O(V + K·logV) | 0.9x | 实时推荐 |
| TopP | O(V·logV) | 0.85x | 实时推荐 |
| Beam Search | O(group_num² × L) | 0.5x | 离线生成、重排 |

注：V=vocab_size(1502), L=层数(3), group_num=5

### 4.2 批量推理优化

```python
# 一次生成多个候选（group_num=5）
output = model.generate(features, group_num=5)
# output["output_ids"]: [B, 5, 3] - 每个用户5个候选

# 去重：确保5个候选不重复
seen = set()
unique_candidates = []
for candidate in output_ids:
    code = tuple(candidate.tolist())
    if code not in seen:
        seen.add(code)
        unique_candidates.append(candidate)
```

## 五、推理后处理详解

生成策略（Beam Search/TopK/TopP）输出的是3层码本ID，还需要经过后处理才能变成最终推荐给用户的内容。

### 5.1 去掉无效码本组合 `valid_urls = urls[sample_mask]`

#### 为什么会有无效组合？

码本虽然是3层，但并不是所有 `[layer1, layer2, layer3]` 的组合都对应真实存在的视频。

```
假设码本大小：
- 第1层：1500 个码字
- 第2层：1500 个码字  
- 第3层：1500 个码字

理论组合数：1500 × 1500 × 1500 = 33.75 亿种
实际视频数：可能只有 1000 万个

有效组合占比：1000万 / 33.75亿 ≈ 0.3%
```

**大部分组合是无效的！**

#### 无效组合的成因

```
训练阶段：
- 模型学习的是"从视频ID → 3层码本"的映射
- 这个映射是 RQ-VAE 或 K-means 生成的

推理阶段：
- 模型生成 [tok1, tok2, tok3]
- 需要去码本查找表中反查对应的视频URL
- 如果 [tok1, tok2, tok3] 在查找表中不存在 → 无效组合
```

#### sample_mask 的作用

```python
# 在 parser/tokenizer.py 中的解码逻辑
def batch_decode_processed(self, output_ids, device):
    """
    output_ids: [B, group_num, 3] - 生成的3层码本ID
    
    返回:
    - urls: 反查得到的URL列表
    - sample_mask: [B, group_num] - 标记哪些组合是有效的
    """
    urls = []
    sample_mask = []
    
    for batch_idx in range(B):
        for beam_idx in range(group_num):
            code = output_ids[batch_idx, beam_idx].tolist()  # [tok1, tok2, tok3]
            
            # 在码本查找表中查询
            url = self.codebook_lookup.get(tuple(code), None)
            
            if url is not None:
                urls.append(url)
                sample_mask.append(True)   # ✅ 有效组合
            else:
                urls.append("INVALID")     # ❌ 无效组合
                sample_mask.append(False)
    
    return urls, torch.tensor(sample_mask)

# 使用
valid_urls = urls[sample_mask]  # 只保留有效的URL
```

#### 实际例子

```python
# 假设生成了5个候选
generated_codes = [
    [100, 200, 50],    # ✅ 有效 → URL: "https://video1.com"
    [150, 300, 80],    # ❌ 无效（查无此组合）
    [120, 220, 60],    # ✅ 有效 → URL: "https://video2.com"
    [999, 888, 777],   # ❌ 无效（查无此组合）
    [110, 210, 55],    # ✅ 有效 → URL: "https://video3.com"
]

sample_mask = [True, False, True, False, True]

# 过滤后
valid_urls = ["https://video1.com", "https://video2.com", "https://video3.com"]
# 从5个候选变成3个有效候选
```

#### 为什么需要过滤？

| 问题 | 说明 |
|------|------|
| **不能推荐不存在的视频** | 无效组合无法映射到真实URL |
| **影响评估指标** | 如果不过滤，hitrate 会被拉低 |
| **用户体验** | 推荐了一个打不开的链接 |

### 5.2 多样性重排 `diversity_rerank(valid_urls)`

#### 为什么需要多样性？

即使都是有效URL，也可能出现以下问题：

```
问题1: 重复推荐
  候选1: "猫吃饭视频A"
  候选2: "猫吃饭视频B"（和A几乎一样）
  候选3: "猫吃饭视频C"（和A几乎一样）
  → 用户看到的都是雷同内容！

问题2: 主题单一
  候选1: "篮球精彩进球"
  候选2: "篮球教学"
  候选3: "篮球比赛"
  → 用户可能还想看足球、乒乓球！

问题3: 同一作者
  候选1: "UP主X的搞笑视频1"
  候选2: "UP主X的搞笑视频2"
  候选3: "UP主X的搞笑视频3"
  → 全是同一个人的！
```

#### diversity_rerank 的核心思想

```python
def diversity_rerank(urls, top_k=5):
    """
    从候选URL中选择 top_k 个，保证多样性
    
    策略1: 去重（基于视频特征相似度）
    策略2: 作者打散（避免同一作者连续出现）
    策略3: 标签打散（覆盖不同主题）
    策略4: MMR（最大边缘相关）
    """
    
    selected = []
    candidates = urls.copy()
    
    while len(selected) < top_k and candidates:
        if not selected:
            # 第一个选分数最高的
            best = max(candidates, key=lambda x: x['score'])
        else:
            # 后续选择：既高分又与已选不相似的
            best = None
            best_score = -float('inf')
            
            for candidate in candidates:
                # MMR 分数 = λ * relevance - (1-λ) * max_similarity(selected)
                relevance = candidate['score']  # 相关性（模型分数）
                
                # 计算与已选的最大相似度
                max_sim = max([similarity(candidate, s) for s in selected])
                
                # MMR 公式
                mmr_score = 0.7 * relevance - 0.3 * max_sim
                
                if mmr_score > best_score:
                    best_score = mmr_score
                    best = candidate
        
        selected.append(best)
        candidates.remove(best)
    
    return selected
```

#### 多样性度量方法

**方法1: 基于视频Tag的相似度**

```python
def similarity_by_tag(video1, video2):
    """
    基于视频标签的Jaccard相似度
    """
    tags1 = set(video1['tags'])  # {'猫', '萌宠', '搞笑'}
    tags2 = set(video2['tags'])  # {'猫', '萌宠', '吃饭'}
    
    intersection = len(tags1 & tags2)  # 2 ('猫', '萌宠')
    union = len(tags1 | tags2)         # 4 ('猫', '萌宠', '搞笑', '吃饭')
    
    return intersection / union  # 2/4 = 0.5
```

**方法2: 基于Embedding的余弦相似度**

```python
def similarity_by_embedding(video1, video2):
    """
    基于视频向量表示的余弦相似度
    """
    emb1 = video1['embedding']  # [768] 视频标题+封面图的向量
    emb2 = video2['embedding']  # [768]
    
    return torch.cosine_similarity(emb1, emb2, dim=0)
```

**方法3: 基于作者的去重**

```python
def penalize_same_author(candidate, selected):
    """
    如果候选和已选是同一作者，降低分数
    """
    penalty = 0
    for s in selected:
        if candidate['author_id'] == s['author_id']:
            penalty += 0.3  # 每次重复扣0.3分
    
    return candidate['score'] - penalty
```

#### MMR (Maximal Marginal Relevance) 算法

```
MMR 分数 = λ × 相关性 - (1-λ) × 最大相似度

参数:
- λ = 0.7 (相关性权重)
- 1-λ = 0.3 (多样性权重)

例子：
已选: [视频A(猫)]
候选: 
  - 视频B(猫, score=0.9, sim(A,B)=0.9) → MMR = 0.7×0.9 - 0.3×0.9 = 0.36
  - 视频C(狗, score=0.8, sim(A,C)=0.1) → MMR = 0.7×0.8 - 0.3×0.1 = 0.53 ← 胜出！
  
虽然视频B分数更高，但和A太像了，所以选C！
```

## 七、总结

### 7.1 生成策略对比

| 策略 | 核心思想 | 命中率 | 多样性 | 推荐场景 |
|------|----------|--------|--------|----------|
| **Beam Search** | 保留多个候选，全局最优 | ⭐⭐⭐⭐⭐ | ⭐⭐ | 生产环境（要指标） |
| **TopK** | 限定候选池，随机采样 | ⭐⭐⭐ | ⭐⭐⭐⭐ | 需要多样性 |
| **TopP** | 动态候选池，自适应 | ⭐⭐⭐⭐ | ⭐⭐⭐ | 平衡选择 |
| **Greedy** | 每一步最优 | ⭐⭐ | ⭐ | 测试基线 |

### 7.2 后处理的重要性

| 步骤 | 作用 | 效果 |
|------|------|------|
| **sample_mask 过滤** | 去掉无效码本组合 | 确保推荐的都是真实存在的视频 |
| **diversity_rerank** | MMR多样性重排 | 避免推荐雷同内容，提升用户体验 |

### 7.3 最佳实践

```
1. 生产环境（追求点击率）:
   Beam Search (group_num=5) → 过滤无效 → 多样性重排 → Top5

2. 需要多样性（探索场景）:
   TopK (k=30) → 过滤无效 → 去重 → Top5

3. 平衡选择:
   TopP (p=0.5) → 过滤无效 → 多样性重排 → Top5
```

**关键结论**：
- 追求**点击率**：用 Beam Search（group_num=5）
- 追求**多样性**：用 TopK=30 或 TopP=0.5
- **最佳实践**：先用 Beam Search 生成，再做多样性重排
- **必须后处理**：过滤无效码本组合 + 多样性重排，点击率可从 5% 提升到 8%
