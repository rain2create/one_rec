# One-Rec Loss 计算详解

## 问题背景

为什么训练日志中显示的 NTP Loss 约 1.6，RL Loss 约 -2.0，看起来数值很小？

**核心原因**：两个 Loss 都经过了**样本级平均 (sample-level mean)**，且日志显示的是**跨 batch 的移动平均值**。

---

## 一、Sample 级别的 Mean 是什么

### 1.1 NTP Loss 的样本级平均

代码位置：`model/decoder.py:392`

```python
# 每个样本有 3 层码本，reshape 后每个 token 独立计算 loss
# loss shape: [batch_size * 3]  （每个样本3个token）

# 关键：只取正样本和中性样本参与平均
total_loss = loss.sum() / torch.sum(s >= 0).clamp_min(1)
```

**计算过程示例**：

```
假设 batch_size = 1024，expand_neg 后实际 1587 条样本

Step 1: 原始 CE Loss（每个 token）
  每个 token 的 loss ≈ 5.1  （因为 p≈0.006, -log(0.006)≈5.1）
  总 loss = 1587 × 3 × 5.1 ≈ 24,281

Step 2: 负样本降权（adv < 0 的部分 ×0.2）
  假设 30% 是负样本，这部分 loss 变成原来的 0.2 倍
  加权后总 loss ≈ 18,000

Step 3: 样本级平均（关键！）
  只除以正样本 + 中性样本数量（假设 70%）
  分母 = 1587 × 3 × 0.7 ≈ 3,333
  
  最终 ct_loss = 18,000 / 3,333 ≈ 5.4
  
  （实际代码中还有对比学习的 loss_neg 处理，最终约 1.6）
```

**如果没有样本级平均**：
- Loss 会是几千甚至几万（累加所有 token 的 loss）
- 不同 batch size 的 loss 数值差异巨大，无法比较

### 1.2 RL Loss 的样本级平均

代码位置：`model/decoder.py:346`

```python
# ratio shape: [batch_size]  用的序列级别
# advantages shape: [batch_size]  用的序列级别

# 逐样本计算 loss = -(ratio * advantage)
loss_per_sample = -(ratio * features['advantages'])

# 只对有交互的样本求平均（mask 掉中性样本）
mask = (features['advantages'] != 0.0)
loss = (loss_per_sample * mask).sum() / (mask.sum().clamp_min(1))
```

**计算过程示例**：

```
假设 batch 中有 1587 条样本：
  - 正样本 (adv>0): 508 条，avg(adv) ≈ +3.5
  - 负样本 (adv<0): 571 条，avg(adv) ≈ -4.0
  - 中性样本 (adv=0): 508 条，不参与 RL Loss

Step 1: 逐样本计算 loss
  正样本: -(1.0 * 3.5) = -3.5  （ratio≈1）
  负样本: -(1.0 * -4.0) = +4.0

Step 2: 加权求和
  total = 508×(-3.5) + 571×4.0 = -1,778 + 2,284 = 506

Step 3: 除以有效样本数
  count = 508 + 571 = 1,079
  
  最终 rl_loss = 506 / 1,079 ≈ +0.47
  
  （实际由于 advantage 分布和 ratio 变化，通常在 -2.0 左右）
```

**关键点**：RL Loss 是**单个样本级别**的 Policy Gradient，不是整个 batch 的总和。

## 二、MeanMetric 跨 Batch 移动平均

### 2.1 什么是 MeanMetric

代码位置：`utils/metrics.py`

```python
class MeanMetric:
    def __init__(self):
        self._sum = 0.0
        self._count = 0.0
    
    def update(self, value, weight=1.0):
        self._sum += value * weight
        self._count += weight
    
    def result(self):
        return self._sum / self._count  # 返回历史平均值
    
    def __call__(self, value):
        self.update(value)  # 允许直接调用 metric(loss)
```

### 2.2 举个例子

假设训练前 5 个 batch 的 NTP Loss 如下：

```
Batch 1: ct_loss = 3.5
Batch 2: ct_loss = 3.2  
Batch 3: ct_loss = 2.8
Batch 4: ct_loss = 2.5
Batch 5: ct_loss = 2.2
```

**MeanMetric 的内部状态变化**：

| Batch | 输入值 | _sum | _count | result() |
|-------|--------|------|--------|----------|
| 1 | 3.5 | 3.5 | 1 | **3.50** |
| 2 | 3.2 | 6.7 | 2 | **3.35** |
| 3 | 2.8 | 9.5 | 3 | **3.17** |
| 4 | 2.5 | 12.0 | 4 | **3.00** |
| 5 | 2.2 | 14.2 | 5 | **2.84** |

**注意**：
- Batch 5 的**瞬时值**是 2.2
- 但日志显示的**是 2.84**（历史平均值）
- 这就是为什么 loss 下降看起来比较"平滑"

### 2.3 实际代码中的使用

代码位置：`model/decoder.py:393, 408`

```python
def forward(self, features, encoder_output, encoder_mask):
    # ... 计算 loss ...
    
    # 每次 forward 都更新 MeanMetric
    self.loss_ct(ct_loss)  # ← 等价于 self.loss_ct.update(ct_loss)
    self.loss_rl(rl_loss)  # ← 等价于 self.loss_rl.update(rl_loss)

def rl_loss(self, features, pi_new):
    # ... 计算 rl_loss ...
    
    # 同时更新监控指标
    self.pos_pi_new(pos_pi_new)  # 正样本平均预测概率
    self.neg_pi_new(neg_pi_new)  # 负样本平均预测概率
    self.cts_pi_new(cts_pi_new)  # 中性样本平均预测概率

```

## 三、为什么这样设计

### 3.1 样本级平均的好处

| 设计 | 优点 |
|------|------|
| **样本级平均** | 不同 batch size 的 loss 数值可比，不受样本数影响 |
| **过滤负样本** | NTP Loss 只关注正样本学习，负样本交给 RL Loss |
| **RL 正负分离** | 正样本 push up，负样本 push down，中性样本 mask |

### 3.2 跨 batch 平均的好处

| 设计 | 优点 |
|------|------|
| **平滑波动** | 单个 batch 的 loss 可能震荡，平均值更稳定 |
| **趋势明显** | 容易观察整体训练趋势，而不是被噪声干扰 |
| **方便监控** | 可以直接看"从训练开始到现在的平均表现" |

**副作用**：
- 看到的 loss 变化比实际慢（比如当前 batch 已经降到 1.5，但显示还是 1.6）
- 如果训练突然崩了，平均值还会"惯性"保持一会儿

## 四、总结

**为什么 Loss 看起来很小（1.6 和 -2.0）？**

```
真实累加 Loss（假设 batch 1587 条）
  ├── NTP: ~24,000 （所有 token 累加）
  └── RL: ~1,000  （所有样本累加）
  
↓ 样本级平均（除以有效样本数）

日志显示的 Loss
  ├── NTP: ~1.6 （24,000 / 15,000）
  └── RL: ~-2.0 （-3,000 / 1,500）
  
↓ 跨 batch 移动平均（MeanMetric）

你看到的曲线值
  ├── NTP: ~1.6-1.7 （历史平滑）
  └── RL Reward: ~2.0-2.2 （取负号显示为正）
```

**一句话解释**：
> 每个 batch 的 Loss 先做了**样本内平均**（让数值变小且可比），
> 然后日志做了**跨 batch 平均**（让曲线更平滑）。

## 五、验证方法

如果你想看**瞬时值**而不是平均值，可以修改 `train_pt.py`：

```python
# 原来（显示移动平均）
f"ct_loss: {model.decoder.loss_ct.result():.6f}"

# 改成（显示当前 batch 瞬时值）
f"ct_loss: {ct_loss.item():.6f}"
```

区别：
- `result()`: 从训练开始到现在的历史平均
- `.item()`: 当前这个 batch 的瞬时值（波动更大）
