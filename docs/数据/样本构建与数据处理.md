### 1.2 样本过滤逻辑（`check_line`）

**作用**：从原始曝光日志中筛选出**有明确交互行为**的样本。

**代码逻辑**（`pt_dataset.py`）：
```python
def check_line(self, line):
    flag = False  # 默认丢弃
    secs = line.strip().split(',')
    
    # === 以下情况标记为保留 (flag = True) ===
    # 1. 取消点赞 (like_c)
    if secs[29] == '1' or secs[89] == '1':
        flag = True
    # 2. 点踩 (dislike)
    if secs[30] == '1':
        flag = True
    # 3. 关注 (follow)
    if secs[31] == '1':
        flag = True
    # 4. 点赞/收藏 (like/favorite)
    if secs[28] == '1' or secs[88] == '1':
        flag = True
    # 5. 面板点击 (panel)
    if secs[32] == '1':
        flag = True
        
    # === 以下情况做降采样保留 ===
    # 6. 快速下滑 (<2s)：只保留 10%
    if float(secs[23]) < 2.0 and secs[22] == '1':
        flag = True if random.random() > 0.9 else False
    # 7. 上滑且完成（从上一条视频上滑进入且播放完成）：只保留 50%
    # f050.last_video=1: 来自上一条视频（上滑进入）
    # f021.is_finish_video=1: 完成播放
    if secs[49] == '1' and secs[20] == '1':
        flag = True if random.random() > 0.5 else False
            
    return flag  # True=保留, False=丢弃
```

**关键说明**：
- `check_line` **不区分正负样本**，只要**有交互行为**就保留,
- 最终被丢弃的是：**无交互行为**的曝光样本（约占 77.6%）-- 快速下滑/上滑且完成
- 过滤后剩余样本进入后续处理流程

### 1.4 样本扩充逻辑（`expand_neg`）

**作用**：通过正样本构造额外的中性样本，增加对比学习信号。

**代码逻辑**（`pt_parser.py`）：
```python
def expand_neg(self, features, alpha=-1.0):
    sample_rate = 1.0
    # 1. 找出所有正样本的索引（advantage > 0）
    url_indexes = self.sample_index(features, sample_rate)  # 正样本索引
    fea_indexes = self.sample_index(features, sample_rate)  # 正样本索引

    for k, v in features.items():
        if k == 'url':
            # 2. URL：使用正样本的 URL 进行 shuffle
            v_shuffle = v[url_indexes]
            features[k] = torch.concat([v, v_shuffle], 0)
        elif k == 'advantages':
            # 3. 新样本的 advantage 设为 0（中性样本）
            advantages = v[url_indexes]
            features[k] = torch.concat([v, torch.zeros_like(advantages)], 0)
        else:
            # 4. 其他特征：使用原始正样本的特征
            v_shuffle = v[fea_indexes]
            features[k] = torch.concat([v, v_shuffle], 0)
```

**扩充规则**（基于训练文件实际分布）：
| 样本类型 | 扩充前 | 扩充后 | 变化 |
|----------|--------|--------|------|
| 正样本 | 47% | 32% | **比例稀释，数量不变** |
| 负样本 | 53% | 36% | **比例稀释，数量不变** |
| 中性样本 | 0% | 32% | **新增正样本数条**（47%）|

**为什么这样做？**
- 原始数据中中性样本虽然多，但缺乏"对比信号"
- 通过正样本 shuffle 构造中性样本，形成 **(正样本, 中性样本)** 对比对
- 让模型学习：相同用户特征下，应该推荐正样本的 URL，而不是中性样本的 URL

**为什么不只保留少量负样本？**

| 方案 | 样本构成（以30天数据为例） | 评估 |
|------|----------|------|
| **方案A**（实际采用）<br>正样本 + 负样本 + 构造中性样本 | 正: ~3,351万<br>负: ~3,779万<br>构造中性: ~3,351万 | ✓ 保留了所有真实交互行为数据<br>✓ 负样本提供真实的"非正例"信号<br>✓ 构造中性样本提供对比学习信号 |
| **方案B**（用户建议）<br>只保留正样本 + 构造中性样本 | 正: ~3,351万<br>构造中性: ~3,351万 | ✗ 丢失 3,779万真实负样本数据<br>✗ 样本多样性不足<br>✗ 构造的中性样本是"假"的，缺乏真实场景多样性 |

**关键原因**：
1. **原始负样本是真实的用户行为**：用户看了视频并给出负反馈（点踩、取消点赞等）
   - 这些样本代表"明确不感兴趣"的内容
   - 模型需要学习：这些内容的预测概率应该**远低于正样本**

2. **样本量问题**：如果只保留正样本，对于 2.3亿参数模型来说正样本可能不足

3. **Loss 计算的本质**：
   ```python
   # 正样本: 标准 CE Loss（最大化预测概率）
   # 负样本: -log(1 - p(y))（最小化预测概率，作为负例）
   # 构造中性样本: 使用正样本特征但 advantage=0，形成对比学习
   ```

### 1.5 训练文件样本分布

**重要区分**：以下数据基于**训练文件 `pos-*.gz`** 的抽样统计，与原始曝光日志文件分布不同。

| 样本类型 | 占比 | Advantage 计算 | 说明 |
|----------|------|----------------|------|
| 正样本 | **~47%** | like/fav +4, follow +4, panel +1, finish (+0.4~2.0) | 有明确正向交互 |
| 负样本 | **~53%** | dislike/like_c -6, skip -0.2 | 有负向交互或跳过 |
| 中性样本 | **0%** | - | 训练文件中已过滤 |

**expand_neg 扩充效果**:
```
输入 batch（过滤后，来自 pos-*.gz）
    ├─ 正样本: ~47%（advantage > 0）
    └─ 负样本: ~53%（advantage < 0）
    
    ↓ expand_neg 扩充（正样本 1:1 构造中性样本）
    
输出 batch（扩充后）
    ├─ 正样本: ~32%（数量不变）
    ├─ 负样本: ~36%（数量不变）
    └─ 中性样本: ~32%（advantage = 0，由正样本构造）
    
扩充率 = 1 + 正样本比例 ≈ 1.47 倍
```

**以 mask_valid_rate = 1.55 为例**:
```
原始 batch_size = 1024
    ↓ 经 expand_neg 后实际样本数
每步约 1024 × 1.55 = 1,587 条
    └─ 正样本: ~508 条, 负样本: ~571 条, 中性样本: ~508 条
```

### 1.6 Advantage 详细计算逻辑

```python
# 基础权重计算
w = 0
w += (like == '1' or favorite == '1') * 4      # 点赞/收藏 +4
w -= (like_c == '1' or favorite_c == '1') * 6  # 取消点赞/收藏 -6
w -= (dislike == '1') * 6                       # 点踩 -6
w += (follow == '1') * 4                        # 关注 +4
w += (panel == '1') * 1                         # 面板点击 +1
w += (from_valid_up == 1) * 0.5                 # 有效上滑 +0.5
w += (finish == '1') * 0.4                      # 完成播放 +0.4
w -= (skip == '1') * 0.2                        # 快速跳过 -0.2

# 正样本中，没命中历史 tag 的权重翻倍
if w > 0 and not hit_histag_logque:
    w *= 2
```

**分类标准**：
- `w > 0`：正样本（参与 NTP Loss，权重正常）
- `w = 0`：中性样本（参与 NTP Loss，作为对比负例）
- `w < 0`：负样本（NTP Loss 权重降低 ×0.2，主要用于 RL 阶段）

#### 1.8.2 增量训练机制

**什么是增量训练？**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  增量训练（Incremental Training）机制                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  Day 1: 首次训练                                                             │
│  ├─ 加载 20251201, 20251202 两天的数据                                       │
│  ├─ 训练完成后，在目录下创建 .done.2days.onerec_sft_lazy_decoder 标记文件     │
│  └─ 表示这两天数据已训练完成                                                 │
│                                                                              │
│  Day 2: 增量训练（新数据 20251203 进来）                                      │
│  ├─ 加载最近 2 天：20251202, 20251203                                        │
│  ├─ 20251202 已有 done 标记，跳过                                            │
│  ├─ 20251203 无标记，加载训练                                                │
│  └─ 训练完成后，在 20251203 下创建 done 标记                                  │
│                                                                              │
│  代码逻辑（pt_dataset.py）：                                                  │
│  ```python                                                                    │
│  # 只加载没有 done_spec 标记的目录                                            │
│  done_dirs = filter(lambda x: not os.path.exists("{}.{}".format(x, done_spec)))
│  ```                                                                          │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

**作用**：
- 避免重复训练旧数据
- 每天只需训练新进入的数据
- 模型持续学习最新的用户行为

#### 1.8.3 gradient_accumulation_steps=1 的含义

**问题**：`gradient_accumulation_steps=1` 是什么意思？

**答案**：
- **=1**：每个 batch 计算完 loss 后立即反向传播并更新参数
- **=N**：每 N 个 batch 的梯度累加后才更新一次参数

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  gradient_accumulation_steps = 1（当前配置）                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  Step 1:  Forward  →  Loss  →  Backward  →  Update                          │
│  Step 2:  Forward  →  Loss  →  Backward  →  Update                          │
│  Step 3:  Forward  →  Loss  →  Backward  →  Update                          │
│                                                                              │
│  每个 step 独立更新参数                                                       │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│  gradient_accumulation_steps = 4（示例）                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  Step 1:  Forward  →  Loss  →  Backward  →  累积梯度                         │
│  Step 2:  Forward  →  Loss  →  Backward  →  累积梯度                         │
│  Step 3:  Forward  →  Loss  →  Backward  →  累积梯度                         │
│  Step 4:  Forward  →  Loss  →  Backward  →  累积梯度 →  Update              │
│                                                                              │
│  每 4 个 step 才更新一次参数，等效 batch_size × 4                            │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

**当前配置 =1 的含义**：
- 每处理 1024 条样本（1 个 batch）就更新一次模型参数
- 没有梯度累积，训练速度较快
- 需要较大的显存（因为不分割梯度）

### 1.10 NTP Loss 样本使用策略

```python
# NTP Loss 计算逻辑
s = features['advantages'].repeat_interleave(3, dim=0)  # 每个样本重复3次（3层码本）

# 正样本：标准 CE Loss
# 中性样本：使用 1 - p(y) 作为 loss（对比学习思想）
loss_neg = -torch.log(1e-6 + 1.0 - torch.exp(loss * -1.0))

# 负样本（ad < 0）：权重降低 ×0.2
loss_neg = torch.where(s < 0.0, loss_neg * 0.2, loss_neg)

# 最终 loss：只使用正样本 + 中性样本（ad >= 0）
loss = torch.where(s > 0.0, loss, loss_neg).sum() / torch.sum(s >= 0).clamp_min(1)
```

**结论**：
- NTP Loss 主要使用 **正样本 + 中性样本**（ad >= 0）
- 真实负样本（ad < 0）在预训练阶段权重被降低，主要用于 RL 阶段
- expand_neg 构造的中性样本作为**对比负例**，帮助模型学习区分正负样本
