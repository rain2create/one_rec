# 码本第三层分配策略实验

RQ-KMeans 训练完三层聚类中心后，对**新视频**分配第三层码字（T3）有三种方案，做了对比实验。

---

## 背景

第一层、第二层都是正常 KMeans：找距离最近的聚类中心作为码字。

第三层的问题在于：KMeans 会把语义相似的视频聚到同一个 (T1, T2, T3) 里，导致 Decoder 生成同一组 token 时召回一堆相似视频，重复率很高。

---

## 三种方案

### BASE：三层都用 KMeans

```
T1 = 最近邻(embedding, 第1层聚类中心)
T2 = 最近邻(残差1, 第2层聚类中心)
T3 = 最近邻(残差2, 第3层聚类中心)   ← 正常跑第3轮 KMeans
```

问题：相似视频被归到同一个 (T1, T2, T3)，重复率极高。

---

### hash@3：第三层用 hash 函数

```
T1 = 最近邻(embedding, 第1层聚类中心)
T2 = 最近邻(残差1, 第2层聚类中心)
T3 = xxhash(md5) % 1500              ← 对视频 md5 做哈希取模
```

**hash 函数的含义**：把视频 md5（字符串）映射成一个整数，再对 1500 取模落到 0-1499。

```
md5 = "29da24498b96ca9ca2ab55b7ddcfb93b"
xxhash(md5) = 14839201748293847562
14839201748293847562 % 1500 = 812   → T3 = 812

md5 = "6a46124c72b09694d76447a8780430fa"
xxhash(md5) = 8374920183746291053
8374920183746291053 % 1500 = 303    → T3 = 303
```

性质：
- 同一个视频每次算出的 T3 固定不变
- 不同视频的 T3 看起来随机，均匀分散在 0-1499
- 不依赖任何语义，只看 md5 本身

效果：同 (T1, T2) 下的视频被散开到不同 T3，重复率大幅下降。

---

### sort@3：第三层按顺序分配（轮询）

```
T1 = 最近邻(embedding, 第1层聚类中心)
T2 = 最近邻(残差1, 第2层聚类中心)
T3 = 该 (T1, T2) 桶内已有视频数量 % 1500   ← 按到来顺序依次分配
```

```
(T1=5, T2=12) 桶里已有 47 个视频
新来的视频 → T3 = 47 % 1500 = 47
下一个     → T3 = 48 % 1500 = 48
...
```

同一个 (T1, T2) 下的视频按顺序轮流分到 T3=1, 2, 3, ...，每个 (T1, T2, T3) 最多只有 1 个视频。

---

## 实验结果

| 方案 | 重复率 | like_hits | que_hits | sess_hits | 生成URL数 | like_hitrate | pos_hitrate |
|---|---|---|---|---|---|---|---|
| BASE | 0.3497 | 11,080 | 26,967 | 15,696 | 59,229 | 0.0672 | 0.1028 |
| hash@3 | 0.0346 | 15,515 | 29,661 | 22,655 | 19,266 | 0.0920 | 0.1135 |
| sort@3 | **0.0031** | 15,459 | 27,221 | 20,525 | 36,928 | 0.0907 | 0.1041 |

---

## 结论

- **BASE 重复率 34.97%**：KMeans 把相似视频聚在一起，生成时大量重复
- **hash@3 重复率 3.46%**：hitrate 最高，但生成 URL 数最少（19,266），多样性受限
- **sort@3 重复率 0.31%**：重复率最低，生成 URL 数（36,928）远多于 hash@3，综合最优

**最终选用 sort@3**，即 `upload_new.py` 里的轮询计数方案。
