#### H. Loss：一个 GRPO 代理 × 四种 advantage

##### H.0 reward 是什么

远端 reward 模型一次 forward 吐 **9 维 logits**，客户端用固定权重点积成标量（`train_grpo_neg_sample.py:165, 231-233`）：

```python
# 9 维 reward 顺序（line 164）
# right_click_pred, dt_pred, finish_pred, like_pred, zmtlink_pred,
# follow_pred, dislike_pred, skip_pred, last_pred
reward_weights = torch.tensor(
    [1., 0., 0., 1., 1., 1., 0., 0., 0.], device=device)
rewards = scorer.predict(reward_input_combined)              # [B*(G+1), 9]
rewards = (rewards * reward_weights).sum(-1)                 # → 标量
```

| idx | 名称 | 含义 | 权重 |
|---|---|---|---|
| 0 | `right_click_pred` | 右滑 / 作者面板等主动正反馈 | **1.0** ✅ |
| 1 | `dt_pred` | dwell time | 0 ❌ |
| 2 | `finish_pred` | 完播 | 0 ❌ |
| 3 | `like_pred` | 点赞 | **1.0** ✅ |
| 4 | `zmtlink_pred` | 作者主页 / 深度链接 | **1.0** ✅ |
| 5 | `follow_pred` | 关注 | **1.0** ✅ |
| 6 | `dislike_pred` | dislike | 0 ❌ |
| 7 | `skip_pred` | 短停 skip | 0 ❌ |
| 8 | `last_pred` | 上滑下一条 | 0 ❌ |

```
scalar_reward = right_click + like + zmtlink + follow
              （dt / finish / dislike / skip / last 权重 0）
```

**reward 模型本体**：外部线上"多塔 MMoE 精排模型"，OneRec **直接复用线上精排服务**（TF Serving gRPC `10.177.75.200:9503`，`signature='serving_default'`，shape `[B,n,9]`，本脚本只取 `scores[:,0,:]`）。OneRec 没训过它；缺点：OneRec RL 上限**被精排打分能力锚定**。

##### H.1 代理目标本体

RL 只有**一个 loss 函数**——GRPO/PPO-clip (`train_grpo_neg_sample.py:66-84`)：

```python
def compute_sample_loss(old_log_prob, new_log_prob, advantage,
                        token_wise=False, clip_epsilon=0.1, weight=0.3):
    ratio = torch.exp(new_log_prob) / torch.exp(old_log_prob)
    s1 = ratio * advantage
    s2 = torch.clamp(ratio, 1-clip_ε, 1+clip_ε) * advantage
    return -weight * torch.min(s1, s2).mean()
```

调 4 次，4 种 advantage 各管一件事：

| 调用 | advantage 算法 | 来源 | 学什么 |
|---|---|---|---|
| **grpo** (主) | `(rewards - mean) / std` 组内归一化 | 在线 reward 模型 (gRPC) | reward 高拉高、低压低 |
| **gbpo** (监督) | `±1` (`rl_label==1`→+1) | 离线真实 label | 真实正↑、真实负↓ |
| **legal** (合法) | `sample_mask` (反解成功=1) | 反解器 | 拉合法码本 |
| **prior** (去热) | `-counts^1` 标准化，仅保留负值 | batch 内 `output_ids` 频次 | 压热门，扎堆候选↓ |

**调用代码**（`train_grpo_neg_sample.py:296-303`）：

```python
gbpo_advantage = torch.where(rl_label == 0, -1., 1.)
gbpo_loss   = compute_sample_loss(old, new, gbpo_advantage,      clip_epsilon=0.0, weight=1.0)
legal_loss  = compute_sample_loss(old, new, decoding_advantages, clip_epsilon=0.2, weight=1.0)
prior_loss  = compute_sample_loss(old, new, prior_advantages,    clip_epsilon=0.2, weight=1.0)
grpo_loss   = compute_sample_loss(old, new, advantages,          clip_epsilon=0.2, weight=1.0)
loss = 0.2*gbpo + grpo + 1.5*legal + 2.0*prior
```

| 调用 | clip_ε | token_wise | weight 入参 | 外部加权 | 作用样本数 |
|---|---|---|---|---|---|
| `grpo` | 0.2 | True | 1.0 | × 1.0 | B×G 生成候选 |
| `gbpo` | **0.0**（退化朴素 PG） | True | 1.0 | × 0.2 | 每用户 1 条真实曝光 |
| `legal` | 0.2 | True | 1.0 | × 1.5 | B×G 生成候选 |
| `prior` | 0.2 | True | 1.0 | × 2.0 | B×G 生成候选 |

**外部权重比 `0.2 : 1 : 1.5 : 2` 解读**

| 子项 | 外部权重 | 主要解决 |
|---|---|---|
| `prior` × 2.0 | 最高 | 多样性救场（防扎堆同几条热门） |
| `legal` × 1.5 | 高 | 反解失败率高（强制合法码本组合） |
| `grpo` × 1.0 | 基准 | 主 RL 目标 |
| `gbpo` × 0.2 | 最低 | 监督锚定，避免和 RL 打架 |

> 一句话：`compute_sample_loss` 就是 GRPO，调 4 次只塞了 4 种 advantage——分管"reward 高低 / 真实喜好 / 反解合法 / 反扎堆"。

##### H.2 `prior_loss` 完整链路（去热）

`train_grpo_neg_sample.py:243-246`：

```python
# 注释（关键证据）：
# "根据counts_per_row打压adavantage, 构造一个均值为0，方差为1的热度reward"
alpha = 1.0
scores           = -counts_per_row.to(torch.float).pow(alpha)         # 取负 ★
prior_advantages = (scores - scores.mean()) / scores.std()            # z-score
prior_advantages = torch.where(prior_advantages >= 0, 0., prior_advantages)  # 只留负
```

**关键三步**

1. `scores = -count^α`：count 越大、score 越小（负得越多）
2. z-score 标准化：爆款变成**负值**，长尾变成正值（因为取了负号，整个方向反过来）
3. `torch.where(>=0, 0, x)`：**正的部分（即长尾）清零，只保留负的（即爆款）**

**一个具体例子**

假设 batch 里 4 条候选 URL，它们在语料里出现次数：

| URL | `counts_per_row` | `scores = -count` | z-score | 经 `where` 处理 |
|---|---|---|---|---|
| 爆款 A | 1000 | -1000 | -1.5（远低于均值）| **-1.5（保留）** |
| 爆款 B | 500  | -500  | -0.7 | **-0.7（保留）** |
| 长尾 C | 50   | -50   | +0.7 | 0（清零） |
| 长尾 D | 10   | -10   | +1.5 | 0（清零） |

> 注意 `scores` 列已经取了负号，**count 越大 → score 越小（更负）**。所以 z-score 后爆款变负、长尾变正，跟直接对 count 做 z-score 完全反过来。

**进 PPO loss 的物理效果**

```python
loss = -mean(ratio * advantage)
```

- 爆款 advantage < 0 → 要让 loss 小 → 让 ratio 小 → `new_log_prob < old_log_prob` → **压低爆款 URL 的生成概率**
- 长尾 advantage = 0 → **不参与梯度**

**净效果：压低爆款生成概率，长尾不动**——这就是"去热"的实现机制。

**与 grpo 配合**

| Loss | 信号方向 | 作用 |
|---|---|---|
| **grpo** | 推高 reward 高的、压低 reward 低的 | 按用户偏好"推" |
| **prior** | 仅压低组内爆款（z-score < 0 的）| 反扎堆"压" |

一推一压：grpo 让模型生成用户喜欢的，prior 让模型生成的候选不要全挤在几条头部爆款上。

#### 3.4.1 为什么 A 必须"预测"、B 可以"真实"？

```
范式 A RL（每用户 1+10）：
   ┌──────────────────────┐    ┌─────────────────────────────┐
   │ 1 条真实曝光 url     │ +  │ 10 条 beam search 新生成    │
   │ ✅ 有真实 label      │    │ ❌ 没有任何 label           │
   └──────────┬───────────┘    └──────────┬──────────────────┘
              │                            │
        gbpo: ±1 真实              grpo: reward 模型预测

范式 B PT（每用户 1）：
   ┌──────────────────────┐
   │ 仅 1 条真实曝光 url  │    ← 不 beam、不生成
   │ ✅ 有真实 label      │
   └──────────┬───────────┘
              │
         直接读 label 加权 (like+4, follow+4, dislike−6 …)
```

| 范式 | 打分对象 | 有真实 label？ | 怎么办 |
|---|---|---|---|
| A grpo | beam 生成的 **新** url | ❌ | reward 模型预测 |
| A gbpo | 曝光的 **真实** url | ✅ | 直接 ±1 |
| B rl_loss | 曝光的真实 url | ✅ | 直接硬编码加权 |

> A "预测+真实" 两路并行不是冗余——同 batch 同时存在两类 url；B 砍掉 grpo 路、只保留并精细化 gbpo 路。

| 范式 | 优势 | 代价 |
|---|---|---|
| A | 能探索从未曝光的 url（grpo 引导生成空间） | reward 服务 + 偏差传递 |
| B | 工程简单（无 serving、无 beam、纯本地） | 只能在曝光过的 url 空间调整；权重靠人调 |

> 一句话：A 用预测**因为它给没见过的 url 打分**；B 用真实**因为它根本不给没见过的 url 打分**。

### 3.6 Loss（对比 NTP + offline 策略梯度 + Aux）

`decoder.py forward()` (lines 384-407):

```python
loss = self.loss_fn(output_logits, masked_labels)            # NTP CE per-token

# ① 对比项：根据 advantage 符号切分
s = features['advantages'].repeat_interleave(3, dim=0)
loss_neg = -torch.log(1e-6 + 1.0 - torch.exp(loss * -1.0))
loss_neg = torch.where(s < 0.0, loss_neg * 0.2, loss_neg)     # dislike 弱化到 0.2
loss = torch.where(s > 0.0, loss, loss_neg).sum() / clamp(...)
self.loss_ct(loss)

# ② aux loss
loss = loss + 0.01 * MANAGER.aggregate_aux_loss()

# ③ rl loss
loss = loss + rl_loss
self.loss_rl(rl_loss)
```

| 子项 | 强度 | 适用样本 |
|---|---|---|
| 正样本 (s>0) | 标准 CE：`-log p(target)` | 正向 |
| 对比负 (s==0) | `-log(1 − p(target))` | 中性 |
| 真实负 (s<0) | 上面 × 0.2 | dislike |
| `aux_loss` | × 0.01 | MoE 均衡 |
| `rl_loss` | × 1.0 | 全样本按 advantage 加权 |

`decoder.rl_loss` (lines 316-354):

```python
pi_safe = torch.where(features['advantages'] > 0.0, pi_new, 1.0 - pi_new)
ratio   = pi_new / pi_safe.detach()
mask    = (features['advantages'] != 0.0)
loss    = -(ratio * features['advantages'])
loss    = (loss * mask).sum() / mask.sum().clamp_min(1)
```

> Offline policy gradient：advantage 来自 §3.4 parse-time 现算，**不调 reward 服务、不 beam search、不 on-policy 采样**——是给曝光样本按规则加权，不是真 RL。

**与范式 A 三阶段最终对照**

| 维度 | 范式 A | 范式 B |
|---|---|---|
| ntp loss | PT/SFT 标准 CE | 同 + 对比 `loss_neg` 分支 |
| RL 信号 | 独立脚本 + beam + gRPC | PT 内 `rl_loss`，规则 advantage 加权 |
| reward 计算 | 训练时在线 gRPC（9 维多目标） | parse 时本地按硬编码权重 |
| 候选生成 | beam G=10 | ❌ 不生成 |
| 优势计算 | 组内归一化 + 多路 | 直接读 `features['advantages']`，无归一化 |
| PPO clip | ε=0.2 | ❌ 朴素 PG |
