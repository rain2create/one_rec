# One-Rec 离线评测指标说明

## 一、评测数据：三个用户行为序列

测试集中每个用户包含 **三类历史行为序列**，分别对应 CSV 的不同字段组：

```
┌──────────────────────┬─────────────────────┬──────────────────────────┬──────────────┐
│ 序列名称             │ 代码变量            │ CSV字段                   │ 含义          │
├──────────────────────┼─────────────────────┼──────────────────────────┼──────────────┤
│ 正反馈序列 (like)    │ logreallike_lmcode  │ f091-f099                │ 用户明确点赞/ │
│                      │                     │                          │ 收藏的视频    │
├──────────────────────┼─────────────────────┼──────────────────────────┼──────────────┤
│ 长时行为序列 (que)   │ logque_lmcode       │ f080-f088                │ 用户长期观看  │
│                      │                     │                          │ 过的所有视频  │
├──────────────────────┼─────────────────────┼──────────────────────────┼──────────────┤
│ 短时行为序列 (sess)  │ logsess_lmcode      │ f044-f079                │ 用户当前      │
│                      │                     │                          │ session的视频 │
└──────────────────────┴─────────────────────┴──────────────────────────┴──────────────┘
```

- 每个序列存储的是 **3层码本ID** `[tok1, tok2, tok3]`，用 `_` 拼接为字符串，如 `"100_200_50"`
- 解析函数 `parse_his()` 将其转为 `["100_200_50", "101_201_51", ...]` 列表

核心评测脚本：`test_by_feature_metrics_seq_enc.py`（老版本为 `test_by_feature_metrics.py`）

## 二、评测流程（逐步）

### Step 1: 模型生成候选

```python
# 对每个用户，用 Beam Search 生成 100 个候选码本
res = model.generate(inputs, group_num=100)    # bs_rl_generate_mask
output_ids = res["output_ids"]                 # [100, 3] — 100个候选，每个3层码本
```

### Step 2: 码本解码为 URL

```python
# 将码本ID反查为视频URL（无效组合返回空字符串）
urls = url_tokenizer.batch_decode(output_ids)
urls = [x for x in urls if x != '']            # 过滤无效码本组合
urls_hashid = pt_parser._hash_to_tensor(np.asarray(urls), 20000019).tolist()
```

### Step 3: 计算命中

```python
def cal_hits(his_ids, r_ids):
    """计算生成结果与历史序列的交集"""
    his_set = set(his_ids)                     # 用户历史去重
    return len(his_set), len(his_set & set(r_ids))
    #      ↑ 历史item总数    ↑ 生成结果命中数

def parse_his(his_seq):
    """将历史序列中的码本ID转为可比对的标准格式"""
    his_seq = his_seq.tolist() if type(his_seq) is not list else his_seq
    [x for x in his_seq if x != '1501_1501_1501']      # 过滤无效填充
    return ['_'.join([str(y) for y in x]) for x in his_seq]
```

核心逻辑：**看模型生成的 100 个候选码本中，有多少个是用户历史上实际看过/点赞过的**。

### Step 4: 累加统计

```python
metrics = [0] * 11

# 正反馈序列 (like)
a, b = cal_hits(parse_his(loglik_ids), parse_his(output_ids))
metrics[0] += a    # like_his
metrics[1] += b    # like_hits

# 长时行为序列 (que)
a, b = cal_hits(parse_his(logque_ids), parse_his(output_ids))
metrics[2] += a    # que_his
metrics[3] += b    # que_hits

# 短时行为序列 (sess)
a, b = cal_hits(parse_his(logses_ids), parse_his(output_ids))
metrics[4] += a    # sess_his
metrics[5] += b    # sess_hits

metrics[6] = len(urls_recall)      # 全局去重URL数
metrics[7] += len(urls)            # 总生成URL数
metrics[8] += len(valid_urls)      # 有效URL数（非空）
metrics[10] = gini(urls_recall)    # URL分布Gini系数
```

```
┌──────────┬────────────────────┬──────────────────────────────────────┐
│ 索引     │ 名称               │ 含义                                 │
├──────────┼────────────────────┼──────────────────────────────────────┤
│ [0]      │ like_his           │ 测试集中正反馈(like)序列去重item总数  │
│ [1]      │ like_hits          │ 生成结果命中正反馈序列的item数        │
│ [2]      │ que_his            │ 测试集中长时行为(que)序列去重item总数 │
│ [3]      │ que_hits           │ 生成结果命中长时行为序列的item数      │
│ [4]      │ sess_his           │ 测试集中短时行为(sess)序列去重item总数│
│ [5]      │ sess_hits          │ 生成结果命中短时行为序列的item数      │
│ [6]      │ recall_urls        │ 全局去重后的生成URL总数（set size）   │
│ [7]      │ total_urls         │ 总生成URL数（含空字符串）             │
│ [8]      │ valid_urls         │ 有效URL数（非空字符串）               │
│ [9]      │ pool_urls          │ 在全量URL池中存在的URL数              │

└──────────┴────────────────────┴──────────────────────────────────────┘
```

### 命中率计算

```python
like_hitrate = metrics[1] / metrics[0]    # like_hits / like_his
pos_hitrate  = metrics[3] / metrics[2]    # que_hits  / que_his
```

- `pos_hitrate` 用 `que_hits / que_his` 计算，因为长时行为序列（logQue）包含了用户的正向行为信号，所以称为 "pos"（positive）
- `like_hitrate` 更严格，只算明确的正反馈行为（点赞/收藏）

## 五、评测本质：Recall@K 留出法

```
评测逻辑：
  输入：用户A的历史行为特征（不含目标视频本身）
  输出：模型生成 100 个候选视频

  Ground Truth = 用户A历史中实际看过/点赞过的视频集合
  命中 = 候选 ∩ Ground Truth

  命中率 = |候选 ∩ Ground Truth| / |Ground Truth|

本质是 Recall@100：
  "给模型用户历史特征，看模型能否'回忆'起用户之前看过/点赞过的视频"
```

## 六、流式数据中的用户重复问题

### 6.1 现状：不做用户去重

当前评测**以每条曝光日志为独立样本**，不对用户去重。同一个用户在不同时间的多次曝光，各算一条独立样本。

```
CSV行1: uid=A, 特征=(昨天看的30条视频), 目标视频=url_1
CSV行2: uid=A, 特征=(今天看的30条视频), 目标视频=url_2   ← 同一用户，不同时间窗口
CSV行3: uid=B, 特征=(昨天看的30条视频), 目标视频=url_3

三条样本权重相同，全部独立累加
```

### 6.2 对指标的影响

```
┌──────────────────────────────────────────────────────────────────┐
│  假设测试集有3条样本：                                             │
│                                                                   │
│  用户A（第1次）: like历史=[v1, v2, v3], 生成=[v1, v5, v8]        │
│    → like_his += 3, like_hits += 1                               │
│                                                                   │
│  用户A（第2次）: like历史=[v1, v2, v3, v4], 生成=[v2, v6, v9]    │
│    → like_his += 4, like_hits += 1                               │
│                                                                   │
│  用户B（第1次）: like历史=[v10, v11], 生成=[v10, v12]             │
│    → like_his += 2, like_hits += 1                               │
│                                                                   │
│  最终: like_hitrate = (1+1+1) / (3+4+2) = 33.3%                  │
│  ⚠️ 活跃用户A贡献了 78% 的分母，指标被高频用户主导                 │
└──────────────────────────────────────────────────────────────────┘
```

### 6.3 各指标受用户重复的影响

```
┌──────────────┬────────────────────────────┬───────────────────────────┐
│ 指标         │ 去重方式                   │ 受高频用户影响程度         │
├──────────────┼────────────────────────────┼───────────────────────────┤
│ like_his     │ 每条样本独立计数           │ ⭐⭐⭐ 严重，分母被主导     │
│ like_hits    │ 每条样本独立计数           │ ⭐⭐⭐ 严重                 │
│ que_his      │ 每条样本独立计数           │ ⭐⭐⭐ 严重                 │
│ que_hits     │ 每条样本独立计数           │ ⭐⭐⭐ 严重                 │
│ recall_urls  │ 全局 set 去重              │ ⭐ 轻微（生成内容偏向）    │
│ Gini系数     │ 基于去重后的 URL 频率      │ ⭐ 轻微                    │
└──────────────┴────────────────────────────┴───────────────────────────┘
```

只有 `recall_urls`（`metrics[6]`）做了全局去重——不管同一个 URL 被多少个用户命中多少次，只算 1 次。这就是为什么 `recall_urls` 只有 3-6 万，而 `like_his` 有 16-28 万。

### 6.4 当前做法的合理性

```
优点：
  ✅ 实现简单，直接累加即可
  ✅ 每条曝光 = 一次真实推荐机会，高频用户确实贡献更多线上流量
  ✅ 与线上 A/B 测试统计方式一致（按请求计而非按用户计）

缺点：
  ✗ 指标被高频用户主导，低频用户的体验被掩盖
  ✗ 不同实验间如果用户分布不同，不可直接对比
  ✗ 无法做 per-user 的显著性检验
  ✗ 实验记录中也提到"需要一个更稳定的评测生成多样性的指标"
```

### 6.5 Per-User 评测方案（如需改进）

```python
# 按用户聚合的评测方式
user_metrics = {}  # {uid: {"his": set(), "hits": set()}}

for sample in dataloader:
    uid = sample['uid']
    if uid not in user_metrics:
        user_metrics[uid] = {"his": set(), "hits": set()}

    # 同一个uid的历史累积（去重）
    user_metrics[uid]["his"].update(parse_his(loglik_ids))
    # 同一个uid的命中累积（去重）
    user_metrics[uid]["hits"].update(
        set(parse_his(loglik_ids)) & set(parse_his(output_ids))
    )

# 计算 per-user hitrate，再平均（每个用户权重相同）
per_user_hitrates = [
    len(m["hits"]) / len(m["his"])
    for m in user_metrics.values() if len(m["his"]) > 0
]
mean_hitrate = np.mean(per_user_hitrates)
```

这样每个用户权重相同，高频用户不再主导指标。

## 七、总结

```
┌──────────────────────────────────────────────────────────────────┐
│ 离线评测核心公式：                                                │
│                                                                   │
│ like_hitrate = Σ(每条样本的like_hits) / Σ(每条样本的like_his)     │
│ pos_hitrate  = Σ(每条样本的que_hits)  / Σ(每条样本的que_his)      │
│                                                                   │
│ 方式：按请求（曝光事件）累加，不做用户去重                         │
│ 含义：在所有测试曝光中，模型猜中用户历史视频的比例                  │
│ 偏倚：高频用户贡献更多样本，指标更多反映活跃用户的表现              │
│                                                                   │
│ 如需用户级别公平评测：按uid聚合 → 算per-user hitrate → 求均值      │
└──────────────────────────────────────────────────────────────────┘
```
